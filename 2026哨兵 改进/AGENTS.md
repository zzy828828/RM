# 项目协作说明

本文件适用于本目录及所有子目录。若子目录另有 `AGENTS.md`，其规则在对应范围内补充本文件。默认用中文交流和编写项目说明。

## 项目与构建入口

- 本项目是 RM C 型开发板上的 STM32F407 步兵机器人固件，使用 C、STM32 HAL、FreeRTOS 和 CMSIS-RTOS。
- Keil 工程：`MDK-ARM/standard_tpye_c.uvprojx`；目标名称：`standard_tpye_c`；设备配置：`STM32F407IG`。
- CubeMX 配置：`standard_tpye_c.ioc`。
- 保留已有名称中的 `tpye` 拼写，不要因拼写问题擅自重命名工程、目标或配置文件。
- 以 Keil 工程中的编译器配置、文件清单、宏和包含路径为准。不要假定存在 CMake、Make 或通用主机测试入口。
- 本目录不一定是 Git 仓库；使用 Git 前先检查，不要自动初始化仓库、提交或清理文件。

## 先查实现，再下结论

- 源码是当前行为的依据，Markdown、历史注释和以前的对话可能过期。文档与代码不一致时沿调用链核实，不要仅修改文案来迎合旧结论。
- 控制输入核对 `remote_control.c/.h`、`chassis_behaviour.c`、`gimbal_behaviour.c`、`shoot.c`、`servo_task.c` 以及对应头文件。
- 区分“定义了宏或枚举”“存在函数”“函数实际被调用”“当前输入能够进入该状态”。不能把保留的单发函数写成已经启用的单发操作。
- 多种输入并存时检查优先级、状态保持、恢复路径和特殊分支。两个拨杆同时向下会进入键盘模式保持分支，不能笼统描述为立即停止所有运动。
- `Ctrl+Z/X/C` 与舵机任务的 `Z/X/C` 存在重叠；涉及快捷键修改时同时检查两条路径。
- CAN 发送检查 `CAN_receive.h` 的总线宏及发送函数；接收检查 `bsp_can.c` 和接收回调。当前发送宏均指向 `hcan1`，但两个 CAN 接收均开启且回调按 ID 解析，不能据此说 CAN2 完全未使用。
- 摩擦轮参数检查 `bsp_fric.h` 和 `shoot.c` 中斜坡上限、就绪条件；PWM 命令达到阈值不代表电机实际转速已达到要求。
- 校准检查 `calibrate_task.c/.h`、`INS_task.c` 和云台状态机。区分板上 Flash 校准数据保存与电调 ID 设置；不要把电调行为写成主控已确认的结果。
- 离线恢复要检查后续控制周期：单次赋值为 STOP 不等于锁存停止，也不等于必须重新操作拨杆。

## 修改约定

- 先阅读相关文件和调用方，实施与请求直接相关的改动，保留用户已有修改。
- 沿用相邻代码的缩进、命名、类型和接口风格；不做无关的全文件格式化或批量重命名。
- 多个旧 C 文件含有非 UTF-8 或已损坏的中文注释。避免仅因显示乱码重写整个文件；修改前确认编码，尽量局部修改并保留换行风格。
- 不擅自升级或改写 `Drivers/`、`Middlewares/` 中的厂商代码；确需修改时说明具体原因和影响。
- 修改 CubeMX 生成文件时优先使用 `USER CODE` 区域。外设配置变更同时核对 `.ioc` 与生成代码，不通过无关的全量重新生成覆盖业务修改。
- 新增或移动 C 文件时同步 Keil 工程文件清单；检查头文件包含路径，不能只把文件放入目录就认定会参与编译。
- 不手工改写已有 `.bin`、`.hex`、`.axf`、`.o`、`.crf`、`.lst` 等构建输出，也不把旧二进制当作本次编译结果。不要随意覆盖用户的 `.uvguix.*` 配置。

## 实时与硬件边界

- 中断、DMA 回调和高频控制循环内避免阻塞等待、动态内存分配和高频打印。检查新增代码的执行时间、任务栈以及共享数据访问方式。
- 改动 PID、反馈符号、安装矩阵、控制周期或单位换算时，明确角度/角速度单位、正方向、积分限幅和输出限幅；不要同时随意改变相互耦合的参数。
- 保留遥控离线、无力模式、电流限制、热量限制和堵转处理等已有保护逻辑，除非任务明确要求调整并已分析其影响。
- 编辑、静态检查和编译不等于实际烧录或设备控制。烧录、擦除 Flash、重设电调 ID、发送运动命令前确认这些操作已在用户授权范围内，并核对具体目标。
- 实机运动测试按涉及部件安排：底盘可靠架空、发射机构卸弹、云台运动空间与线束检查。失稳或持续顶限位时先切断驱动电源；不要求用户用手抵住通电运动机构来完成测试。
