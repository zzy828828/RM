# 板载陀螺仪使用分析报告

本文已按当前源码复核。固件实际使用 RM C 型开发板上的 BMI088 陀螺仪和加速度计完成姿态解算；云台和底盘均依赖该结果。

## 1. 初始化与任务

`Src/freertos.c` 以 `osPriorityRealtime` 创建 `INS_task`，栈大小为 1024。任务启动后：

1. 等待初始化延时。
2. 循环初始化 BMI088，失败时每 100 ms 重试。
3. 初始化 IST8310。
4. 读取一次 BMI088 原始数据。
5. 初始化 IMU 温控 PID 和 AHRS。
6. 启动 SPI DMA 数据链路并持续更新姿态。

IST8310 的周期读取调用当前被注释，磁力计数据并未正常进入每次姿态更新。

## 2. 数据采集

BMI088 的加速度计和陀螺仪数据就绪引脚触发 `HAL_GPIO_EXTI_Callback()`：

- 加速度计中断调用 `detect_hook(BOARD_ACCEL_TOE)`。
- 陀螺仪中断调用 `detect_hook(BOARD_GYRO_TOE)`。
- 中断置位更新标志，由 SPI DMA 读取寄存器数据。
- DMA 完成后解析为 `bmi088_real_data.accel/gyro/temp`。

这种结构避免任务轮询等待 SPI，提高了姿态更新的实时性。

## 3. 坐标转换与零漂

陀螺仪和加速度计共用当前安装矩阵：

```text
[ 0  1  0 ]
[-1  0  0 ]
[ 0  0  1 ]
```

`imu_cali_slove()` 对原始三轴数据应用该矩阵，并叠加校准偏置。其含义是当前板级 X/Y 轴在软件坐标中进行了 90° 旋转，Z 轴方向保持不变。

机械安装方向必须与矩阵一致；零漂校准只能修正静态偏置，不能修正轴交换或正负号错误。

## 4. 姿态解算

加速度数据经过滤波后，`AHRS_update()` 使用陀螺仪、加速度计和当前磁力计数组更新四元数，`get_angle()` 输出：

- `INS_angle[0]`：Yaw，单位 rad。
- `INS_angle[1]`：Pitch，单位 rad。
- `INS_angle[2]`：Roll，单位 rad。

对外接口包括：

- `get_INS_angle_point()`：姿态角。
- `get_gyro_data_point()`：旋转角速度。
- `get_accel_data_point()`：加速度。

## 5. 使用位置

### 云台

`gimbal_init()` 保存 INS 角度和角速度指针。正常绝对角度模式使用 INS Yaw/Pitch 作为角度反馈，并使用对应轴角速度完成速度环控制。

云台自动校准也利用 Pitch/Yaw 角速度判断是否已经稳定到机械限位。

### 底盘

`chassis_init()` 保存 INS 角度指针。`chassis_feedback_update()` 用 INS 姿态角减去云台电机相对角，估算底盘 Yaw/Pitch；Roll 直接取 INS Roll。

因此 BMI088 方向或姿态解算异常会同时影响云台稳定和底盘跟随。

## 6. 温控

INS 任务读取 BMI088 温度并调用 `imu_temp_control()`。陀螺仪校准被遥控器触发时，固件把目标温度更新为触发时 MCU 温度加 10 ℃，并限制在 `GYRO_CONST_MAX_TEMP` 内。

## 7. 零漂校准

触发手势：左右拨杆都向下，先双摇杆下内八保持 2 秒，再在 20 秒内双摇杆下外八保持 2 秒。

校准过程：

1. 暂停 DBUS 接收，防止机器人运动。
2. 连续约 20 秒采集静止陀螺仪输出并迭代偏置。
3. 比例系数保持 `1.0f`。
4. 把三轴偏置写入 Flash。
5. 恢复遥控器接收并关闭校准蜂鸣器。

校准期间必须保持机器人水平静止并远离振动源。

## 8. 离线检测

BMI088 陀螺仪和加速度计分别对应 `BOARD_GYRO_TOE`、`BOARD_ACCEL_TOE`。数据就绪中断持续调用检测钩子；超过设定时间没有更新就会被判定为离线。

IST8310 的数据就绪中断仍可更新 `BOARD_MAG_TOE`，但由于周期读取被注释，不应把“磁力计在线”理解为“磁力计数据正在参与有效闭环”。

## 9. 结论

- BMI088 是当前云台稳定与底盘姿态估计的核心传感器。
- 数据路径为数据就绪中断、SPI DMA、坐标变换、偏置补偿、AHRS、Yaw/Pitch/Roll 输出。
- 机械安装方向、旋转矩阵、零漂和温控都必须正确。
- 零漂校准不能补偿错误安装方向。
